# Билеты на мероприятия в «Продуктах» — дизайн

Дата: 2026-09-26. Статус: согласовано с владельцем.

## Цель

Продавать билеты на свои творческие вечера в разделе `/products/`. Гости — в основном знакомые; на входе билеты не проверяются. Минимум возни: одно поле (e-mail для чека), билет — картинка PNG для скачивания на странице заказа, писем покупателю не шлём (чек присылает Т-Банк). Данные конкретного вечера владелец внесёт позже через админку.

Правовая рамка (исследование 26.09.2026): ИП, исполняющий свои произведения, — «организация исполнительских искусств» (ст. 36.2 Основ законодательства о культуре), поэтому: форма электронного билета по приказу Минкультуры № 702, цены и правила возврата на сайте, шкала возврата ст. 52.1 / ПП № 1491. НДС нет (УСН, доход < 20 млн); льгота пп. 20 п. 2 ст. 149 НК ИП недоступна и не нужна.

## Решения

- Третий вид товара: `products.kind = 'event'` (наряду с `physical`, `digital`).
- Вместимость — существующая таблица `variants`, один вариант `size='-'`: `stock` = свободные места, `reserved` = в резерве на время оплаты (20 мин). Оплата: `stock -= qty, reserved -= qty` (ветка мерча «в наличии»); истёк/отменён до оплаты — `reserved -= qty`; отмена оплаченного с возвратом — `stock += qty` (место возвращается в продажу). Предзаказа нет.
- Остаток на сайте: `left = max(0, stock - reserved)`.
- Заказ: 1–5 билетов, только e-mail + галочки оферты и согласия. Заказ помечается `delivery_mode = 'event'`.
- Продажа закрыта, если `event_at` уже наступил (сервер решает по своим часам).
- Чек: одна позиция `Билет: <название>, <ДД.ММ.ГГГГ ЧЧ:ММ>`, `qty` билетов, `PaymentObject: service`, `PaymentMethod: full_payment` (билет как документ, удостоверяющий право прохода, передаётся в момент оплаты — распространённая практика билетных продавцов).
- Писем покупателю нет. Владельцу — обычное письмо о заказе без ПД (сейчас не доходит: Postbox ждёт DNS; ошибка пишется в `mail_error`, заказ не страдает).
- Билет — PNG, рисуется в браузере (canvas) на странице заказа из ответа `status`; на сервере не хранится. Номер билета = номер заказа.
- Возврат — вручную кнопкой «Отменить и вернуть деньги» в админке; шкала — в оферте.
- Время мероприятия хранится ISO UTC, показывается по Москве (`Europe/Moscow`).

```

ALTER TABLE products ADD COLUMN venue Utf8;      -- место, текстом (адрес)
ALTER TABLE products ADD COLUMN age_mark Utf8;   -- '0+'|'6+'|'12+'|'16+'|'18+'
```

## API (merch-api, `?a=`) — контракт для фронтенда

- `catalog&kind=digital` — раздел «Продукты»: товары `digital` **и** `event`. Для `event` в элементе дополнительно: `event_at`, `venue`, `age_mark`, `left` (int), `sales_open` (bool: `event_at` в будущем и `left > 0`). `catalog` без kind — по-прежнему только physical.
- `product&s=` — для `event` те же поля: `kind:'event'`, `event_at`, `venue`, `age_mark`, `left`, `sales_open`; плюс `qty_max` (5).
- `order` (POST), event: тело `{ product_id, email, qty, offer: true, consent: true }`. Ошибки: 400 `validation` `{field: email|qty|offer|consent}`, 409 `sold_out` (мест меньше, чем qty), 409 `sales_closed`, 404 `no_product`. Ответ `{ id, k, paymentUrl }`. failUrl → `/products/order/?id=&k=&fail=1`, success → редирект на `/products/order/?id=&k=`.
- `status&id=&k=` — для event: `kind:'event'`, `can_download:false`, и при статусе `paid`|`done` объект `ticket`: `{ number, title, event_at, venue, age_mark, qty, price_item, total }`. ПД не отдаются.
- Админ: `admin/product` принимает `kind:'event'`, `event_at` (ISO или пусто), `venue`, `age_mark` (из списка или пусто), `variants: [{size:'-', stock:N}]` — свободные места. `admin/products` отдаёт `kind` как есть (`event` не превращается в physical) и новые поля. `admin/summary.to_ship` не считает event. Для event-заказа кнопки «Собран/Отправлен» нет, отмена с возвратом — есть.

## Сайт

- `/products/` — карточка мероприятия: картинка, название, дата/время (МСК), цена, «осталось N мест» / «мест нет» / «продажа закрыта».
- `/products/p/?s=` (kind event) — картинка, название, дата/время, место, возрастной знак, описание, цена, «Осталось мест: N», выбор количества 1…min(5, left), поле «E-mail для чека», галочки оферты и согласия, кнопка «Купить N билет(а) за X ₽». Под кнопкой — правила возврата: «Вернуть билет: за 10 дней и раньше — 100%, за 5–9 дней — 50%, за 3–4 дня — 30%, позже — нет. Если вечер отменится — 100%. Пишите на dimaantiosov@yandex.ru с номером заказа.» Ошибки `sold_out`/`sales_closed` — понятным текстом, обновить остаток.
- `/products/order/?id=&k=` (kind event, paid|done) — заголовок, крупно «Скачайте и сохраните билет», картинка билета, кнопка «Скачать билет (PNG)». Билет содержит реквизиты формы приказа № 702: «Электронный билет», номер, название, дата и время, место, возрастной знак, количество, цена, «ИП Антиосов Д. А., ИНН 771402577192».
- Админка: тип «мероприятие» → поля «Дата и время», «Место», «Возрастной знак», «Свободных мест»; в списке товаров — дата и «свободно N / резерв R»; в заказе — «билетов: N».
- Оферта `/offer/`: раздел о билетах (что получает покупатель, билет = номер заказа) и шкала возврата в п. 6; новая дата редакции.

## Проверка

- Тесты `merch-api/test/event.test.js` на `antiosov-merch-test`: каталог отдаёт event в `kind=digital` с `left`; заказ без ПД, резерв qty, чек service; `sold_out` при нехватке; `sales_closed` после `event_at`; оплата → `stock -= qty`, писем покупателю нет; `status` отдаёт `ticket` только после оплаты; отмена оплаченного → `stock += qty`; истечение → резерв снят.
- Живое: миграция prod, деплой, тестовое мероприятие `event-test` (1 ₽, 60 мест) — страницы в браузере до платёжной страницы Т-Банка, отрисовка билета на странице заказа; после проверки товар выключается.
