# Рассылка писем подписчикам (2026-10-06)

Цель: Антиосов изредка пишет письма (книги, вечера, вещи) тем, кто сам согласился. ФЗ «О рекламе» ст. 18 — только с предварительного согласия, доказывает отправитель; 152-ФЗ — согласие на ПД с этой целью отдельно. Маркировка/ОРД к e-mail не применяется.

## Галочка в формах заказа

Формы: `merch/p/index.html`, `products/p/index.html` (+ `python3 products/build-pages.py` → карточки `/products/<slug>/`), `products/buy-block.js`.
Третья галочка после «оферты» и «согласия на ПД», `name="news"`, **не отмечена, не обязательна**. Подпись — текст автора дословно, затем ссылка:

> я не против, если Антиосов будет мне иногда присылать письма. А Антиосов точно не будет присылать письма часто, делать ему нечего письма строчить, он же не CRM-маркетолог какой. <a href="/consent/rassylka/">(документик)</a>

В тело заказа уходит `news: true|false`. Форма ВСД (пейволл) — вне объёма.

## Юридические тексты

- Новая страница `/consent/rassylka/` (стиль как `/consent/`): кто (ИП Антиосов, реквизиты как в `/consent/`), что (письма о книгах, вечерах, вещах и других проектах Антиосова, в т.ч. рекламного характера, не чаще чем изредка), данные (только e-mail), срок (до отзыва), отзыв (ссылка «Отписаться» в каждом письме или письмо на dimaantiosov@yandex.ru), после отзыва адрес удаляется. Версия текста — `NEWS_CONSENT_VER = '2026-10-06'`.
- `/merch/privacy/`: добавить цель «рассылка писем — только с отдельного согласия» со ссылкой на `/consent/rassylka/`.
- `/consent/` не меняется (цели заказа отдельно от рассылки).

## Данные

```
CREATE TABLE subscribers (email Utf8, token Utf8, consent_at Timestamp, consent_ver Utf8, source Utf8, PRIMARY KEY (email));
CREATE TABLE mailings (id Utf8, created_at Timestamp, subject Utf8, body Utf8, sent Int32, failed Int32, PRIMARY KEY (id));
```

- `source` — номер заказа (`M-000123`). `token` — 32 hex, для ссылки отписки.
- Повторная галочка тем же адресом → UPSERT: новый `consent_at`/`consent_ver`/`source`, токен сохраняется.
- Отписка → `DELETE` строки. Подписка не зависит от `purgePd` заказов и наоборот.

## Бэкенд (`merch-api`)

- `lib/subscribers.js`: `subscribe(email, source)`, `unsubscribe(email, token)`, `count()`, `list()`, `sendMailing({subject, body, test})`, `listMailings()`.
- `index.js`, `case 'order'`: после успешного `createOrder`, если `body.news === true` и e-mail валиден → `subscribe` (ошибка подписки логируется, заказ не роняет).
- `?a=unsub&e=&t=`: GET → HTML-страница «Вы отписались» (или «Адреса уже нет в списке»); POST (RFC 8058 one-click, тело `List-Unsubscribe=One-Click`) → 200. Неверный токен → тот же ответ «нет в списке» (не раскрываем, подписан ли адрес).
- Письмо рассылки: From `Антиосов <shop@antiosov.ru>`, Reply-To `REPLY_TO`, заголовки `List-Unsubscribe: <https://…?a=unsub&e=…&t=…>` и `List-Unsubscribe-Post: List-Unsubscribe=One-Click`. Текст: тело как есть (text) + HTML с экранированием и кликабельными ссылками; подвал «Вы получили письмо, потому что согласились при заказе на antiosov.ru. Отписаться: <ссылка>».
- Каждому подписчику отдельное письмо, последовательно. Таймаут функции 30 с → при >~40 подписчиках отправка порциями: админка вызывает `admin/mailing` с `offset`, пока не `done` (сервер шлёт до 25 за вызов).
- Админ-маршруты: `GET admin/subscribers` (число + список e-mail/дата/источник), `POST admin/mailing` `{subject, body, test:true}` → только на `OWNER_EMAIL`; `{subject, body, mailing_id?, offset}` → порция всем; `GET admin/mailings` — журнал.

## Админка (`/merch/admin/`)

Вкладка «Рассылка»: число подписчиков (раскрывающийся список), поля «Тема», «Текст», кнопки «Отправить себе» и «Отправить всем (N)» (confirm), прогресс по порциям, журнал (дата, тема, ушло/ошибок).

## Проверка

- Unit: subscribe/upsert/unsubscribe (неверный токен не удаляет), заголовки и подвал письма (через подмену `ext.mail`), порционная отправка, `news:false` не подписывает.
- Живая (после верификации Postbox): заказ с галочкой на выключенном тестовом товаре (включить на секунды) → подписчик в админке → «Отправить себе» дошло в Gmail с кнопкой отписки → ссылка «Отписаться» удаляет. Пока Postbox `FAILED` — живая отправка невозможна, это фиксируется как непроверенное.

## Клиенты (добавлено 2026-10-06, по просьбе владельца)

Раздел «Клиенты» в админке — **представление над `orders`, без новой таблицы**: копия ПД жила бы вне `purgePd`; из заказов клиент исчезает сам вместе с обезличенными заказами.

- Ключ клиента — e-mail в нижнем регистре (есть во всех формах). Телефоны и имена — все различные из его заказов. По телефону не склеиваем (общий телефон семьи → ложное слияние).
- Обезличенные заказы (`purgePd`) и заказы без e-mail — не показываем.
- `GET ?a=admin/clients` → `{ clients: [{ email, names[], phones[], orders_total, orders_paid, sum_paid, first_at, last_at, kinds[], subscribed, subscribed_at, orders: [{ id, created_at, status, product_id, product_title, total }] }] }`. «Оплачен» = статус из `paid|packed|shipped|done`; `sum_paid` — сумма `total` таких заказов. `subscribed` — e-mail есть в `subscribers`.
- Админка, вкладка «Клиенты»: таблица (e-mail, телефон, заказов всего/оплачено, сумма, последний заказ, ✉), раскрытие строки → заказы со ссылкой на заказ в админке; фильтр «только кому можно писать», поиск по e-mail/телефону, сортировка по сумме/дате последнего заказа.
