# «Продукты» — продажа цифровых товаров (скиллы для ИИ) — дизайн

Дата: 2026-09-25. Статус: согласовано с владельцем (вариант A — расширить merch-api).

## Цель

Раздел «Продукты» на antiosov.ru: продажа цифровых товаров (первый — скилл «живой русский», zip, 111 ₽; пока не готов и не загружается). Покупка один раз, повторное скачивание последней версии без ограничений. Возврат — пока архив ни разу не скачан (оферта `/offer/`, п. 6).

## Решения

- Бэкенд — существующая функция `merch-api` (заказы, Т-Банк, чеки, админка, письма уже работают). Товар получает признак `kind`.
- Для цифрового заказа собираем только e-mail (минимизация ПД) + две отдельные галочки: оферта и согласие (156-ФЗ).
- Чек: `PaymentObject: intellectual_activity`, `PaymentMethod: full_payment`, без доставки.
- Архив — в закрытом бакете `antiosov-merch`, ключ `d/<product_id>/<hex>.zip` (публично открыт только `p/*`). Выдача — presigned GET на 10 минут.
- Отметка первого скачивания `downloaded_at` — основание правила возврата.
- Картинка товара — обычное фото товара (`p/*`), загружается через существующую админку. Генерирует владелец (промпт в стиле ВСД).

## Данные (YDB, ALTER TABLE ADD COLUMN — неразрушающая миграция)

- `products.kind Utf8` — `'digital'` | `'physical'`; пусто/NULL = physical (все старые товары).
- `products.file_key Utf8` — ключ архива в бакете, пусто = архив не загружен.
- `orders.downloaded_at Timestamp` — первое скачивание (NULL = не скачивал).
- `orders.download_count Int32` — число скачиваний (NULL = 0).

## API (merch-api, `?a=`)

- `catalog` — по умолчанию только physical (витрина мерча не меняется); `catalog&kind=digital` — только digital. Поле `kind` в каждом товаре.
- `product&s=` — добавляется `kind`, `has_file` (bool). `file_key` наружу не отдаётся.
- `order` (POST), цифровой товар: тело `{ product_id, email, offer: true, consent: true }`. Проверки: email, offer, consent; товар активен и `has_file`, иначе 409 `no_file`. qty=1, size `'-'`, без резерва/вариантов, `price_delivery=0`, `delivery_mode='none'`, имя/телефон/адрес — пустые. Ответ как у мерча: `{ id, k, paymentUrl }`. successUrl → `?a=success`, failUrl → `/products/order/?id=&k=&fail=1`.
- `success` — для цифрового заказа редирект на `/products/order/?id=&k=`.
- `status` — добавляются `kind`, `can_download` (digital и статус `paid`|`done`), `downloaded` (bool). ПД не отдаются.
- `download&id=&k=` (GET) — новый. Если заказ цифровой, ключ верный, статус `paid`|`done`, у товара есть `file_key`: при первом вызове пишет `downloaded_at`, всегда `download_count += 1`, 302 на presigned GET (600 с, `response-content-disposition: attachment; filename="<product_id>.zip"`). Иначе 403 `not_paid` / 404 `no_order` / 409 `no_file`.
- Админ: `admin/product` принимает `kind`, `file_key` (ключ должен соответствовать `^d/<id>/[0-9a-f]+\.zip$` или быть пустым). `admin/file` (POST `{product_id}`) → `{ key, put_url }` (presigned PUT, `application/zip`, 600 с). `admin/orders` отдаёт `downloaded_at`, `download_count`, `kind` товара.
- Отмена/возврат цифрового заказа — существующий `admin/order {action:'cancel'}` из `paid`; без операций с вариантами. Предупреждение о скачивании — в UI админки.

## Домен (lib/orders.js)

- `createOrder`: ветка digital — без транзакции резерва по variants; номер из общего счётчика (`M-000123`).
- `confirmPaid`: для digital не трогает variants; `afterPaid`: письмо владельцу (без ПД) и покупателю «Доступ открыт» со ссылкой на `/products/order/?id=&k=`; без Яндекс Доставки.
- `releaseNew`/`gc`: для digital не трогают variants.
- `cancel`: для digital не трогает variants.

## Сайт

- Главная: строка «Продукты» → `/products/` в списке разделов.
- `/products/` — каталог (`catalog&kind=digital`), пусто → «скоро».
- `/products/p/?s=` — карточка: картинка, описание, цена, блок «Как установить» (текст ниже), форма: e-mail, галочка оферты, галочка согласия, кнопка «Купить за N ₽».
- `/products/order/?id=&k=` — статус; при `can_download` — кнопка «Скачать» (`?a=download`), блок «Как установить», строка про возврат до первого скачивания.
- Админка `/merch/admin/`: у товара выбор «вещь / цифровой»; для цифрового — загрузка zip (через `admin/file` + PUT) и отображение, загружен ли архив; в списке заказов у цифровых — «скачан ДД.ММ / не скачан».

Текст «Как установить» (утверждён владельцем):

> 1. Скачайте архив.
> 2. Откройте чат со своим ИИ: Claude, ChatGPT, Codex или любым другим.
> 3. Приложите архив и напишите: «Установи этот скилл».
>
> ИИ установит его сам или подскажет, куда нажать. Если скиллы он не поддерживает, напишите: «Прочитай SKILL.md и работай по нему».

## Проверка

- Юнит/интеграционные тесты на `antiosov-merch-test`: создание цифрового заказа (без ПД, без вариантов), отказ без offer/consent/файла, оплата → письма, `download` до оплаты → 403, после → 302 + `downloaded_at`, повтор → `download_count=2`, отмена с возвратом, `catalog` разделяет kind, `status` без ПД.
- Живое: деплой, миграция prod, тестовый товар `skill-test` (1 ₽, тестовый zip), проверка страниц в браузере до платёжной страницы Т-Банка; товар после проверки выключается. Реальную оплату 1 ₽ проводит владелец.
